# Magnet OS benchmark matrix

Reviewed 2026-09-25. References below are current official documentation/product pages researched during this review, not independent product trials. Recommendations are Magnet-specific inferences, not promises of parity, pricing or availability. No competitor UI is copied. Current behavior is from repository functions and the read-only reconciliation inventory, not inferred from feature names.

| Magnet Module | Reference Products | Useful Pattern | Current Magnet Behavior | Gap | Recommended Magnet Solution |
|---|---|---|---|---|---|

| Canonical data/Studio | [Airtable linked records](https://support.airtable.com/articles/1484376934-understanding-linked-record-relationships-in-airtable), [Notion relations](https://www.notion.com/help/relations-and-rollups) | Different views should reference the same entity | Projections, JSON records, unused typed tables, standalone localStorage Studio | Duplicate authorities and disconnected document identity | Explicit legacy-to-canonical mapping; Studio documents reference client/project IDs, never create a second client universe |

## What not to import

Do not import every feature, commercial plan limitation, notification retention rule, AI suggestion or public-sharing default. In particular, suggested record matches are review candidates, never authority to merge business identities. An agency needs trustworthy handoffs more than another board view.

The Current Magnet Behavior column records the pre-remediation baseline. See the audit's remediation section for changes implemented after comparison; server migration candidates remain unapplied remotely.
